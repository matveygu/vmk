# Обновление и новые учебные функции

## Одной командой (Docker)

Запустите Docker Desktop. В PowerShell из любой папки:

```powershell
python C:\Users\engtc_pbk5w0m\CLionProjects\vmk\docker\update.py --check
python C:\Users\engtc_pbk5w0m\CLionProjects\vmk\docker\update.py
```

На сервере: `python3 /путь/к/проекту/docker/update.py`.
Команда использует compose и `.env.docker` рядом со скриптом, проверяет рабочую
папку существующего контейнера, собирает образ, сохраняет PostgreSQL и media,
применяет миграции, собирает CSS/JS, пересоздаёт web, ждёт исправного healthcheck
и сверяет версию. Требуется Docker Compose с поддержкой `--wait`.
Версия и тип базы видны только администратору в обзоре админ-панели.
`--check` ничего не меняет. Обновление кратковременно останавливает сайт.

Если обнаружена другая рабочая папка, команда остановится до обновления.
Сначала сравните каталоги `data/media`, `staticfiles` и настройки двух копий:
одинаковое имя проекта Compose не означает одинаковые файлы на диске.
Не меняйте имя проекта `msu-portal` и не используйте `down -v` для обновления.
Резервные копии сохраняются в `data/backups`; отдельно копируйте их вне сервера.
Проверка списка содержимого дампа в backup.py не заменяет пробное восстановление.

При запуске через `runserver` перед запуском выполните `python manage.py migrate`.
В админке проверьте тип базы: локальный запуск может использовать SQLite,
а Docker — PostgreSQL. Это две отдельные базы, их данные не синхронизируются.

## Каталог материалов и мобильная навигация

При загрузке и редактировании файла можно указать предмет и семестр (1–12).
Оба поля необязательны: старые файлы и папки сохраняются без изменений.
Чтобы они попадали в новые фильтры, заполните эти поля через «Изменить».

Поиск по названию и фильтры по предмету, семестру, типу файла и избранному
работают совместно и ищут во всех папках. Без фильтров показывается содержимое
текущей папки. Файлы выводятся по 36 на странице; при переходах условия поиска
сохраняются. Предметы и отметки избранного загружаются без отдельного SQL-запроса
на каждый файл.

Звёздочка рядом с файлом добавляет его в личное избранное. Отметки одного
пользователя не видны другому и не меняют доступ к материалам: как и раньше,
каталог доступен всем вошедшим пользователям. Из дневного расписания и карточки
пары можно перейти к материалам её предмета.

На узких экранах у вошедшего пользователя появилась нижняя панель: главная,
пары, задания и материалы. Боковое меню с остальными разделами сохранено.

Нужна миграция `materials.0004` — скрипт Docker-обновления применяет её автоматически.
Для локального запуска используйте `python manage.py migrate`.

## Домашние задания

В разделе заданий доступны фильтры «Нужно сделать», «Просрочено», «Выполнено»,
«Все». «Нужно сделать» включает и просроченные задания. Отметка выполнения
принадлежит одному пользователю, её можно отменить. Задания без срока не считаются
просроченными. Дата определяется по московскому времени.

## Изменение пары на дату

Администрирование → Расписание → нужная группа и день → «Изменить на дату».
Выберите дату, предмет, время, аудиторию или отмену, добавьте пояснение.
Дата должна соответствовать дню недели и чётности исходной пары.
Смена времени выполняется внутри того же дня; перенос на другой день пока
не поддерживается. Преподаватели наследуются из основной записи.

Проверяются пересечения времени группы, ID преподавателей и точного обозначения
аудитории с учётом других изменений на эту дату. Неопределённое время в старых
записях и разные написания одной аудитории требуют ручной проверки.
Изменения видны на главной, в дневном/недельном личном расписании и в публичном
расписании с выбранной датой. Кнопка восстановления возвращает основную запись.

## Уведомления

Меню → Уведомления. Новое ДЗ и сохранение/отмена изменения пары создают записи
для активных пользователей группы и преподавателей пары. Отметки прочтения
индивидуальны. Повторное сохранение без правок не рассылает дубликаты.
Старые события не загружаются задним числом, email не отправляется.
Публикация новой новости через портал также создаёт уведомление для всех активных
пользователей. Редактирование уже существующей новости не создаёт повторного
уведомления. На главной отображаются
три ближайших невыполненных задания со сроком сегодня или позже.

В `.github/workflows/checks.yml` добавлены проверки Django, миграций, тесты на
SQLite и PostgreSQL и сборка Docker. Они запускаются GitHub после push или
создания pull request; сами эти действия скрипт обновления не выполняет.
