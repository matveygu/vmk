## Оптимизация SQL

Показатели ниже — число запросов при полном рендеринге страниц в изолированных
тестах, а не измерение времени ответа в интернете. Данные и шаблоны одинаковы
до и после оптимизации. Для расписания используется 21 занятие, для диска —
21 папка с вложенной папкой и материалом в каждой, для новостей — 4 записи.

| Страница | Было | Стало |
| --- | ---: | ---: |
| Главная вошедшего пользователя | 48 | 7 |
| Расписание на день | 26 | 5 |
| Расписание на неделю | 53 | 6 |
| Публичное расписание (вошедший посетитель) | 27 | 6 |
| Файловый раздел | 71 | 7 |
| Новости | 9 | 5 |

Предметы/авторы подгружаются вместе с основной выборкой; домашние задания главной
страницы — одним дополнительным запросом. Недельное расписание получает все дни
одной выборкой, наличие заданий определяется через `Exists`. Статистика папок
собирается пакетно. Повторное открытие того же раздела файлов больше не перезаписывает
сессию в БД. Роли, видимость занятий и даты проверяются регрессионными тестами.

Число SQL-запросов теперь не растёт при увеличении тестовой выборки с 1 до 21
занятия/папки. Это не означает постоянное время работы: объём HTML, количество
возвращённых строк и обращения к файловой системе всё ещё зависят от данных.

## Предпросмотр и тестовые файлы

Текстовый предпросмотр читает не более 1 МиБ + 1 байта, показывает уведомление об
усечении и гарантированно закрывает файл. Полное скачивание сохраняется. Это снижает
потребление памяти для больших текстов и устраняет оставшийся открытым файловый дескриптор.

Тестовые загрузки изолированы во временных каталогах и удаляются после тестов;
они больше не накапливаются в рабочем `data/media`. Тесты скачивания проверяют
реальное содержимое потока, включая полный большой файл.

Проверки:

```powershell
docker compose --env-file .env.docker run --rm web python manage.py test main schedule materials --noinput
docker compose --env-file .env.docker run --rm web python manage.py check
```

Проект Compose по-прежнему называется `msu-portal`; перенос каталога не требует
повторного импорта SQLite и не должен создавать новый том PostgreSQL. Команды
запускайте из новой папки. Для обновления привязок файлов используется
`docker compose --env-file .env.docker up -d --force-recreate web`, а не удаление томов.
