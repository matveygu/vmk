# Подтверждение email и восстановление пароля

## Что работает

- При регистрации email обязателен. До подтверждения аккаунт не создаётся.
- Код состоит из 6 цифр, действует 10 минут и допускает 5 попыток ввода.
- Код привязан к браузеру, где началась регистрация. Повторная отправка
  аннулирует старый код. Кнопка «Исправить email или данные» начинает регистрацию заново.
- Вход остаётся по номеру студенческого. После подтверждения email пользователь
  переходит на страницу входа.
- «Забыли пароль?» отправляет ссылку на email аккаунта. Ссылка действует час,
  после смены пароля повторно не используется. Старые сеансы входа теряют доступ.
- Для неизвестного или отключённого аккаунта показывается такое же сообщение,
  но письмо не отправляется. Если у нескольких старых активных аккаунтов одинаковый
  email, администратор должен сначала исправить адреса.

Существующие аккаунты продолжают работать. Если email раньше не был указан,
пользователь может добавить его в профиле; при потере доступа поможет администратор.
Старые адреса в профилях не подтверждаются автоматически задним числом.

## Локальная проверка

В `.env`:

```dotenv
DJANGO_DEBUG=True
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
PORTAL_PUBLIC_URL=http://127.0.0.1:8000
```

Примените миграцию и запустите сервер:

```shell
python manage.py migrate
python manage.py runserver
```

При регистрации код появится в терминале сервера. При восстановлении там появится
ссылка. В этом режиме письма **не доставляются** на настоящие почтовые ящики.
Используйте один адрес сайта: если открываете `localhost`, задайте и
`PORTAL_PUBLIC_URL=http://localhost:8000`.

## Отправка писем на Yandex Cloud

Поддерживается обычный SMTP, в том числе Yandex Cloud Postbox. В Postbox нужно
подтвердить домен отправителя и настроить DNS по инструкции сервиса. Создайте
сервисный аккаунт с правом отправки и API-ключ с областью действия
`yc.postbox.send`. SMTP-логин — идентификатор API-ключа, пароль — его секретная
часть. Параметры описаны в [инструкции Yandex Cloud](https://yandex.cloud/ru/docs/postbox/quickstart).

Укажите на сервере переменные окружения (в `.env` либо в конфигурации сервиса):

```dotenv
DJANGO_DEBUG=False
DJANGO_ALLOWED_HOSTS=portal.example.ru
DJANGO_CSRF_TRUSTED_ORIGINS=https://portal.example.ru
PORTAL_PUBLIC_URL=https://portal.example.ru

EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=postbox.cloud.yandex.net
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
EMAIL_HOST_USER=идентификатор_API_ключа
EMAIL_HOST_PASSWORD=секретная_часть_API_ключа
DEFAULT_FROM_EMAIL=Учебный портал ВМК МГУ <noreply@example.ru>
```

Замените домен сайта, адрес отправителя и ключи своими значениями. Домен отправителя
должен быть подтверждён в Postbox. Секреты не добавляйте в Git. Используйте постоянный
случайный `DJANGO_SECRET_KEY`: его замена аннулирует коды, ссылки и сессии.

Для SMTPS на порту 465 задайте `EMAIL_USE_TLS=False` и `EMAIL_USE_SSL=True`.
Оба режима одновременно включать нельзя. Для другого почтового провайдера
возьмите SMTP-настройки у него. Почтовые услуги могут тарифицироваться отдельно
от виртуальной машины.

`PORTAL_PUBLIC_URL` — точный адрес сайта с `https://`, без пути. Ссылки сброса
строятся из него, а не из заголовка Host посетителя. При переезде замените этот
параметр и настройки разрешённых доменов, затем перезапустите приложение.

После обновления кода выполните `python manage.py migrate` на сервере. Проверяйте
отправку регистрацией своего тестового аккаунта и восстановлением его пароля.
Если сервер почты недоступен, регистрация покажет ошибку; аккаунт не создастся.
На странице сброса сообщение всегда нейтральное; ошибки доставки отмечаются
в журнале приложения как `Password reset delivery failed` без ключей и кодов.

## Ограничения запросов и обслуживание

Для регистрации, повторной отправки и сброса действуют общие ограничения:
1 запрос в минуту и 5 запросов в час на email, 30 запросов в час с одного адреса
соединения (`REMOTE_ADDR`). Ограничители хранятся в базе и работают между процессами.
Не передавайте публичные `X-Forwarded-For` напрямую в `REMOTE_ADDR`. Если приложение
работает за прокси, учитывайте, что адрес соединения может быть общим для посетителей;
настройте доверенную обработку адресов на уровне сервера.

Раз в час можно запускать:

```shell
python manage.py cleanup_email_auth
```

Команда удаляет только истёкшие незавершённые регистрации (включая их персональные
данные и хэши) и истёкшие счётчики. Аккаунты пользователей она не затрагивает.

Проверки без отправки настоящих писем:

```shell
python manage.py test main.test_email_auth
```
